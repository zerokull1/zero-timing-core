# Карта проекта `zero-timing-core` (Путеводитель по папкам и файлам)

Этот файл — наглядная карта всего репозитория. Здесь по полочкам расписано, за что отвечает каждая папка и каждый ключевой файл.

---

## Полка 1. Главное ядро (`src/` и `zero_hal/`)
Сердце системы на чистом `#![no_std]` Rust и ассемблере `x86_64` (без стандартной библиотеки и без `libc`).

| Путь к файлу | Что это такое простыми словами | Как устроено внутри |
| :--- | :--- | :--- |
| `src/lib.rs` | Точка входа библиотеки ядра | Собирает все модули вместе и запрещает небезопасный код без явной проверки. |
| `src/l7_shield.rs` | **Главный L7-сканер** (HTTP, TLS, QUIC, CMS) | Проверяет пакеты за ~20–30 тактов без `if/else` (через `cmov` и SWAR-маски по 8/64 байта за раз). |
| `src/flow_table.rs` | Таблица активных соединений | Хранит состояние потоков в 64-байтных слотах без блокировок (`lock-free CAS`) и хэширует их через `AES-NI + CRC32C`. |
| `src/ttl_guard.rs` | Защита от подмены TTL и фрагментации | Ловит аномальные скачки TTL (попытки обмана DPI) и не даёт вымыть доверенные потоки из кэша. |
| `src/adaptive_gateway.rs` | Самообучающийся сторожевой бот | Сам отслеживает репутацию IP-адресов и ловит ритмичных ИИ-сканеров по отсутствию джиттера (`RDTSC`). |
| `src/pulse_barrier.rs` | Защитный барьер памяти `W^X` | Окружает код в памяти страницами-ловушками `PROT_NONE` и минами `UD2`, при атаке выжигает память. |
| `src/thin_hypervisor.rs` | Микро-гипервизор `Ring -1` (`Intel VT-x`) | Прячет страницы кода в режиме `Execute-Only` (процессор может их выполнять, но никто не может прочитать). |
| `src/l1_ai_agent.rs` | Мини-нейросеть внутри кэша L1 (`AVX2`) | Учится ловить неизвестные атаки прямо в кэше процессора за ~82 такта без обращения к внешней памяти. |
| `src/bpf_control.rs` | Генератор ядерного кода eBPF на лету | Собирает программу для ядра Linux прямо в памяти без вызова внешних компиляторов (`clang`). |
| `src/af_xdp_engine.rs` | Сверхбыстрый сетевой канал `AF_XDP` | Забирает пакеты напрямую из драйвера сетевой карты в память без копирования ядром Linux. |
| `zero_hal/` | Слой совместимости с любым железом | Позволяет ядру собираться под 4 архитектуры: `x86_64` (ПК/серверы), `aarch64` (ARM64), `riscv64` и `s390x` (IBM Z). |

## Полка 2. Готовые запускаемые программы (`src/bin/`)

| Путь к файлу | Назначение |
| :--- | :--- |
| `src/bin/zero_pure_asm_engine.rs` | Автономный движок на чистом ассемблере (~6.7 КБ в кэше `L1i`), 25 тактов на пакет. |
| `src/bin/zero_elastic_core.rs` | Многоядерный движок с балансировкой нагрузки между ядрами (`Work-Stealing`) и привязкой к топологии CPU. |
| `src/bin/core_self_test.rs` | Главный встроенный самотест (`cargo test` / проверка всех атак, CVE и барьеров памяти). |
| `src/bin/zero_guard_daemon.rs` | Фоновый системный демон охраны сетевой карты (~5.6 КБ). |
| `src/bin/zero_top.rs` | Консольный монитор живой статистики в реальном времени. |

## Полка 3. Защита на входе сетевой карты (`xdp_shield/`)
Самый первый рубеж обороны — работает внутри ядра Linux до создания сетевых структур `sk_buff`.

| Путь к файлу | Назначение |
| :--- | :--- |
| `xdp_shield/xdp_zero_shield.c` | Главный ядерный XDP-фильтр: в 1–2 такта отбрасывает поддельные IP, `VLAN VID=0`, `TCP/2049` (NFS2ROOT), `UDP/443` (Zero-QUIC) и обход путей `..;/`. |
| `xdp_shield/tc_egress_failclose.c` | Фильтр на выходе (`TC Egress`): выравнивает исходящий `TTL=65` и закрывает трафик при аварии (`Fail-Close`). |

---

## Полка 4. Загрузка до старта Windows/Linux (`uefi_stage0/`)

| Путь к файлу | Назначение |
| :--- | :--- |
| `uefi_stage0/unikernel_ring0.rs` | Загружается напрямую из BIOS/UEFI до старта ОС: калибрует частоту процессора, включает `Ring -1` (`VT-x`) и глушит сетевые карты до инициализации ядра. |
| `uefi_stage0/pci_nic.rs` | Прямой драйвер сетевой карты по шине PCIe (DMA-кольца без участия ОС). |

## Полка 5. Изолированные модули и полигоны (`modules/`)

| Папка | Что внутри и зачем нужно |
| :--- | :--- |
| `modules/ddr_arena/` | Выделение 2 МБ страниц `HugePages`, установка минного поля `UD2` и запечатывание памяти `W^X` (`ddr_arena.c`, `hw_pmc_profiler.h`, `concurrent_canary_trap.c`). |
| `modules/ddr_bundle/` | Проверка криптоподписи `HMAC-SHA256` до выдачи прав на исполнение (`bundle_loader.c`), аудит константного времени (`constant_time_audit.c`) и фаззеры протоколов. |
| `modules/silicon_ymm_vault/` | Хранение ключей внутри векторных регистров `YMM15` процессора с физическим смывом кэша `clflush` (`ymm_vault_demo.c`, `nt_salt_wipe.c`). |
| `modules/vtx_ept_enclave/` | Аппаратная клетка на базе `/dev/kvm` (`Intel VT-x EPT`), которая мгновенно перехватывает выход кода за пределы своей страницы. |
| `modules/deception_tarpit/` | Ловушка для сканеров: отвечает им с задержкой на границе таймаута (`RTO Jitter`) и зажимает окно `TCP Window = 1`. |
| `modules/ai_agent_watchdog/` | Сторож хоста (`zero-host-guard`): следит за целостностью файлов и замораживает (`SIGSTOP`) самовольных ИИ-агентов. |
